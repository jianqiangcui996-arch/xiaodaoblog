> 一次数据迁移 + 虚拟化搬迁 + 博客上云 + 系统盘克隆的全记录，以及中途踩过的每一个坑。

**摘要**：从一台 i5-4590 的老平台，迁到 i7-12700F 的新平台，再追加一轮主板/固态/散热升级。目标不是"重装系统从头再来"，而是**把数据、虚拟机、自建服务、浏览器收藏、甚至系统本身，原封不动、无缝地搬过去**。整个过程横跨好几周，踩了 robocopy、Hyper-V 网卡、Cloudflare 隧道、精简版 Windows 的 VSS 缺失、注册表盘符映射、技嘉 shell 扩展崩溃、DPAPI 密码跨机失效等一大串坑。这篇把它们一次性讲清楚。

---

## 一、为什么要折腾这一趟

老机器是台"钉子户"：i5-4590、16GB DDR3、GTX 960（2G）、128GB 小固态，跑着 Win10。它同时承担了几个角色——日常办公、开发、以及**一台 24 小时开机的家庭服务器**：里面用 Hyper-V 跑着 Ubuntu 和 Kali 两台虚拟机，对外挂着博客、AI 网关、Home Assistant、1Panel 面板，靠 Cloudflare Tunnel 暴露公网。

问题很现实：**电脑一关，博客和这些服务就 502**。而老平台本身也到了该退休的时候。

于是计划分两步走：

1. **换平台**：新机器上 i7-12700F + RTX 3060 12G + 32GB DDR4 + 256GB SATA 固态，把老机器的一切搬过去。
2. **再升级**：新机器用了一阵后，又追加了技嘉 B660M 小雕主板、一块 512GB PCIe NVMe、650W 电源、360 一体水冷和 6 个机箱风扇——并把系统从 SATA 盘克隆到 NVMe，让 NVMe 当系统盘。

核心诉求始终是四个字：**无缝衔接**。数据不能丢、服务不能断、配置不能重来。

## 二、硬件对比（鲁大师实测）

| 项目 | 老机器 | 新机器（升级前） |
|---|---|---|
| CPU | i5-4590 @ 3.30GHz 四核 | 12 代 i7-12700F |
| 内存 | 16GB DDR3-1600（8G×2） | 32GB DDR4-2666（16G×2） |
| 显卡 | GTX 960 2GB | RTX 3060 12GB |
| 主板 | 微星 H97M-P35 | （后续升级为技嘉 B660M 小雕 DDR4） |
| 系统盘 | 影驰 128GB SATA SSD | 昱联 256GB SATA SSD → **512GB PCIe NVMe** |
| 散热/电源 | 原装风冷 | **650W 电源 + 360 一体水冷 + 6 风扇** |
| 鲁大师综合跑分 | 约 44.6 万 | 约 122 万 |

从 44.6 万到 122 万，综合性能大约 **2.7 倍**，但真正的体感提升在固态和内存——尤其是后面把系统搬到 NVMe 之后。

## 三、迁移全景：五个阶段

我把整件事拆成清晰的阶段，避免"边搬边乱"：

1. **准备**：新机装干净系统、分好区（保持盘符布局一致，避免项目里的绝对路径失效）。
2. **数据迁移**：项目、备份、虚拟机导出包，整体走局域网对拷。
3. **虚拟化与服务切换**：Hyper-V 虚拟机导出导入、Cloudflare 隧道从旧机切到新机、Git/SSH/各类配置迁移。
4. **验证**：逐项打勾——项目能开、git 正常、隧道通、域名可达、虚拟机起得来。
5. **退役**：旧机停服务、退出账号、进入冷备份期。

## 四、数据迁移：robocopy 的稳与狠

几十 GB 的项目、上百 GB 的虚拟机导出包，走的是局域网 SMB + `robocopy` 多线程对拷，全程 **0 失败**，最后逐字节核对源和目标一致。

几个心得：

- **robocopy 的退出码不是 0 就是错**——它 0~7 都算成功（1 是"复制了文件"这种），只有 ≥8 才是真失败。别被"exit=1"吓到。
- 大目录先排除 `node_modules`、`__pycache__`、软链接（`/XJ`），能省大量时间和空间。
- **验证一定要在目标端做**，别信"看起来拷完了"。用文件数 + 总字节数双指标比对。

## 五、虚拟化搬迁：Hyper-V 与隧道的坑

把两台虚拟机（Ubuntu 服务机 + Kali）用 `Export-VM` 导出、到新机 `Import-VM -Register` 就地注册。这里埋了两个坑：

**坑 1：内部虚拟交换机必须先建。** 服务机有一块网卡挂在内部交换机上、配了静态 IP。新机上如果不先建好同名内部交换机就导入，网卡会失配。

**坑 2：netplan 按 MAC 匹配，导入后 MAC 变了。** 重导虚拟机后网卡 MAC 会变，而 netplan 配置里如果写死了旧 MAC，那块网卡就变成 unmanaged、拿不到 IP。教训是——**netplan 用"按网卡名匹配"而不是"按 MAC 匹配"**，对 MAC 变化免疫。

**Cloudflare 隧道的切换**是另一个重点：同一隧道如果新旧两台机器同时挂着 connector，会随机负载均衡，请求可能打到已经该退役的旧机上。所以新机 connector 起来、验证通了之后，**旧机的 cloudflared 服务必须立刻停掉并禁用**。刚装 cloudflared 服务后头几秒会有 QUIC 空窗，报 530/502 是假故障，等连接注册满就好。

## 六、博客上云：关机也不掉线

这是最有价值的一步解耦。博客原本是 Hexo 生成静态页、由家里那台机器提供，靠隧道暴露——**电脑一关就 502**。

迁移方案：

```
GitHub 仓库(Hexo 源码)
      │ push 触发
      ▼
Cloudflare Pages ── 自动构建 hexo generate
      │ 自定义域名
      ▼
访客 → 静态站(永远在线)
        ├─ 评论：Giscus ⇄ GitHub Discussions（零后端）
        └─ 统计：Cloudflare Web Analytics（免费、无 Cookie）
```

关键点：**Cloudflare Tunnel 是出站的**，所以"服务在哪跑"和"域名能不能通"是解耦的。静态内容一旦交给 Pages CDN，就和家里机器彻底无关了。

- **写文章** = 在 GitHub 改 `.md` 提交，几十秒后 Pages 自动重新构建上线，全程不碰家里电脑。
- **评论**换成 Giscus（数据存 GitHub Discussions），免费、永久在线、还自带垃圾评论管理。

**最大的一个坑**：Pages 连上 GitHub 后，默认 **Build command 是空的**，它会把源码仓库当产物直接部署，结果首页 404。必须显式设成 `hexo generate`、输出目录 `public`。另外构建环境默认 UTC，日期会差一天，记得加 `TZ=Asia/Shanghai`。

从此博客这条线彻底和主机解耦，家里机器只在"跑动态服务"时才需要开机。

## 七、安全加固：一台"裸奔"的精简系统

新机装的是一台被过度精简的 Windows——安全审查时发现：**Windows Defender 全套服务被连根移除**（不是禁用，是未安装）、防火墙三个配置文件全关、UAC 被设成"从不通知"、`reagentc`/`RecoveryDrive` 也都不见了。

这些"精简"在迁移期是有代价的（比如后面克隆系统时才发现 VSS 被砍），所以策略是：**先做不影响迁移的加固（防火墙、UAC、装回杀软），把和迁移冲突的（如就地修复系统组件）放到迁移收尾后再处理**。

一个通用教训：**图省事用"优化版/精简版"系统镜像，往往会在你最需要某个功能时（VSS、恢复环境、Defender）发现它被删了**。

## 八、系统盘克隆到 NVMe：本次最硬的一块

升级了 NVMe 后，想把系统从旧的 SATA 盘整体搬到 NVMe、并让 NVMe 第一启动。听起来简单，实际是一场硬仗。

### 8.1 在线克隆为什么失败

第一反应是"系统运行中直接对拷"。用 `robocopy /B` 把整个系统卷镜像到 NVMe，再 `bcdboot` 修引导。文件拷了 130 多 GB，看着快成了——结果**开不了机**。

原因：注册表的几个核心 hive（`SYSTEM/SOFTWARE/SAM/SECURITY/DEFAULT/COMPONENTS`）和用户配置单元的 `NTUSER.DAT/UsrClass.dat`，在系统运行时被内核独占锁定，`robocopy /B` 也拿不到。本想用卷影快照（VSS）绕开——**但这台精简系统把 VSS 工具链砍了**：`vssadmin` 的 create 子命令被移除、`diskshadow` 起不来。在线快照这条路直接死了。

### 8.2 用 reg save 补齐 hive

换思路：`reg save` 能在 hive 处于加载状态时导出一份**一致的副本**，不需要 VSS。于是把六个系统 hive + 用户两个 hive 用 `reg save` 导出、写进克隆盘对应位置，再 `bcdboot`。

这一步暴露了另一个坑：**改 TrustedInstaller 拥有的 `System32` 文件，`Rename-Item`/删除会报"非终止性错误"，try/catch 根本接不住，看着像成功了其实没动**。必须先 `takeown` 夺所有权 + `icacls` 授权，并加 `-ErrorAction Stop` 才能拿到真实结果。

### 8.3 能开机，但黑屏

克隆盘能引导、能进登录、任务管理器也起得来——但**桌面黑屏**。查事件日志发现 `explorer.exe / dwm.exe / LogonUI.exe` 集体以 `0x8000ffff` 崩溃，而且出错路径全是 `V:\Windows\...`（不是 `C:`）。

真相：**克隆盘把自己挂成了 V: 盘符**（因为部署时给它的盘符被写进了注册表 `MountedDevices`），而整个 Windows 的注册表/COM 路径全写死在 `C:\Windows`。系统跑在 V: 上、去找 C: 又是另一块盘 → 组件解析全崩。

修复：离线加载克隆盘的 SYSTEM hive，把 `MountedDevices` 里 `C:` 和 `V:` 两个卷的映射**对调**。这一步，正是专业克隆工具会自动做、而手工 robocopy 不会做的"系统卷重映射"。

盘符修好后，又冒出 `ShellHost.exe` 每 30 秒循环崩溃，出错模块是**技嘉 AppCenter 注入的 `ControlCenter.dll` shell 扩展**。在克隆盘上把它改名禁用 + 断掉注入源服务，才消停。

### 8.4 最终用 DiskGenius 一次搞定

但紧接着又遇到 AppX 框架包、CloudStore、StateRepository 这些**运行中锁死的库文件没拷全**——explorer 加载现代 shell 组件时崩溃。根因是这台机 VSS 被砍，导致**在线克隆天然存在"文件↔注册表↔锁定库"三者时序错位**，手工补是打地鼠。

于是果断换工具：**用 DiskGenius 的"系统迁移"做一致性热克隆**——它自带驱动处理锁定文件、自动完成盘符与引导重映射。一次迁移、一次重启，NVMe 干净进桌面，收工。

**这块最大的教训**：在线 `robocopy + reg save` 造克隆，在 VSS 健全的系统上勉强可行；一旦源系统被精简、VSS 缺失，就该直接上专业克隆工具，别硬撑手工方案。

## 九、几件收尾小事，各有各的坑

**浏览器收藏**：新机打开 Edge 是空的。查下来收藏其实一条没丢——都在旧机迁过来的配置文件里，只是这台机装的是 EdgeCore（内部通道），用的是**另一个空的配置目录**。装上标准版 Edge 后，它直接加载了迁移过来的完整配置，收藏、历史、设置一次性全回来了。

**保存的密码**：收藏能回、密码却不自动填——因为**浏览器密码是用 Windows DPAPI（绑定"这台机器+这个用户"的主密钥）加密的**，跨机器解不开。这不是 bug，是机制。正解是在旧机把密码**导出成 CSV**、再在新机导入（CSV 是明文，用完即删）。

**下载工具接管浏览器**：想做出"点下载链接自动甩给下载器"的迅雷式体验，靠的是**浏览器扩展 + aria2 JSON-RPC**：扩展拦截下载事件、把 URL 通过本地 RPC 交给下载器执行。要点是端口和 RPC 密钥两边一致、下载器常驻后台。

**archive.org 下大文件卡住**：排查发现代理和网络都正常，是 archive.org 的 `/download/` 跳转把连接分到了一个坏节点。换成能连通的节点直链就好了——**遇到"某站下不动"，先分清是本地网络问题还是对方节点问题**。

**AI 网关能不能也 serverless**：博客能上云是因为它是静态的；而网关是**有状态的动态代理**。用 Cloudflare 的托管网关可以覆盖"云上游"那一半，但如果网关还路由到**跑在家里的本地大模型**（内网地址），那部分是**无法 serverless 的**——Cloudflare 边缘节点连不到你家里的私有 IP。结论是"混合架构"，别追求全 serverless。

## 十、踩坑清单（速查表）

| 场景 | 坑 | 解法 |
|---|---|---|
| robocopy | 退出码 1 以为失败 | 0~7 都算成功，≥8 才是错 |
| Hyper-V 导入 | 网卡失配 / 拿不到 IP | 先建内部交换机；netplan 按网卡名而非 MAC 匹配 |
| Cloudflare 隧道 | 新旧双 connector 随机负载 | 新机验证通过后立刻停旧机服务 |
| Pages 部署 | 首页 404 | 显式设 Build command `hexo generate` + 输出 `public`；加 `TZ` |
| 系统克隆 | hive 拷不走、VSS 被砍 | `reg save` 补 hive；或直接用专业克隆工具 |
| 改 System32 文件 | 改名"假成功" | `takeown`+`icacls` 夺权，加 `-ErrorAction Stop` |
| 克隆黑屏① | 系统卷挂成非 C: | 离线对调 hive 里 `MountedDevices` 盘符 |
| 克隆黑屏② | 第三方 shell 扩展崩溃 | 禁用注入源 DLL/服务 |
| 克隆黑屏③ | 锁定库时序错位 | 换 DiskGenius 一致性热克隆 |
| Edge 收藏空 | 用了另一个配置目录 | 装标准版 Edge 加载迁移配置 |
| 密码不回 | DPAPI 跨机失效 | 旧机导出 CSV、新机导入 |
| 下载卡死 | 站点坏节点 | 分清本地网络 vs 对方节点，换直链 |

## 十一、复盘

回头看，这趟迁移真正难的不是"拷数据"，而是**那些"看起来搬过来了、实则因为加密/盘符/时序/权限而失效"的隐性坑**。它们有个共同点：**不报错，只是不动**。

几条想留在结尾的经验：

1. **能用成熟工具就别手搓**。系统克隆这件事，手工 robocopy 方案在健全系统上能跑，但一旦遇到精简系统的 VSS 缺失，专业工具的一致性热克隆才是正解。
2. **"验证"要选对指标**。文件数、字节数、逐字节哈希、能不能真开进桌面——每一步都要有明确的、可证伪的判据，别靠"感觉好了"。
3. **精简/优化版系统是定时炸弹**。Defender、VSS、恢复环境被砍掉时，你往往在最需要它们的那一刻才发现。
4. **静态上云、动态留本地**，是家庭自建服务最务实的架构：博客交给 CDN 做到关机也不掉线，而真正需要本地资源（尤其是本地大模型）的部分，坦然接受它依赖一台常开的机器。

从 i5-4590 到 i7-12700F，从"关机等 502"到"博客 24 小时在线"，从 128G 机械小盘到 NVMe——这趟搬的不只是文件，是一整套围绕"自己掌控数据和服务"的生活方式。

值了。
