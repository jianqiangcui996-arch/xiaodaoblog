<blockquote>
<p>在 <strong>Windows Hyper-V 里的 Ubuntu 26.04 VM</strong>（2 vCPU &#x2F; 3.3G 内存 &#x2F; 无公网入站端口）上，<br>把 <strong>1Panel v2.3.0</strong> 一行装好，从 Windows 桌面直接打开纯中文图形界面管服务器，<br>还能一键拉 AI 应用。<br>下面是这次部署中踩过的坑、绕过的弯路，以及最终落地的完整可复现步骤。</p>
<p>（本文已对面板用户名、密码、tailnet、宿主 IP 等做脱敏处理，仅保留技术结构。）</p>
</blockquote>
<h2 id="TL-DR">TL;DR</h2><ul>
<li><strong>机器</strong>：Hyper-V 里的 Ubuntu 26.04 LTS，2 vCPU &#x2F; 3.3G 内存 &#x2F; 76G 盘。无 GPU、无公网入站，靠宿主 portproxy + Tailscale 访问。</li>
<li><strong>目标</strong>：装 1Panel，从 Windows 桌面直接开图形界面管这台服务器（网站、容器、AI 应用、监控、文件、终端）。</li>
<li><strong>结果</strong>：✅ 装好，<code>http://192.168.100.10:8443/&lt;entrance&gt;</code> 打开即登录，纯中文界面，面板常驻内存 ~50–100M，磁盘只占 229M。</li>
<li><strong>两个最大的坑</strong>：<ol>
<li>1Panel 官方国内安装源 <code>in.1panel.cn</code> 从这台机器<strong>直连 DNS 解析失败</strong>（000）。</li>
<li>包从国内 CDN <code>resource.1panel.pro</code> 用 <code>curl</code> 下载会被 <strong>WAF 限流截断到 11MB &#x2F; 65MB</strong>，校验和永远对不上。</li>
</ol>
</li>
<li><strong>解法</strong>：换用 <code>resource.fit2cloud.com</code>（国际&#x2F;国内都能直连）+ <code>wget</code>（比 curl 完整），校验通过后再装。</li>
</ul>
<p>下面按「为什么 → 环境盘点 → 踩坑 → 最终步骤 → 验证 → 面板里干啥」展开。</p>
<hr>

<ol>
<li><strong>不想在终端里敲一堆 <code>apt</code>、<code>systemctl</code></strong>——要图形界面。</li>
<li><strong>要能管容器</strong>——后面想装各种 AI 应用（Ollama、vLLM、ComfyUI、Dify…）都是 Docker 镜像。</li>
<li><strong>要轻</strong>——机器只有 3.3G 内存，面板常驻不能太吃。</li>
<li><strong>要纯中文</strong>、免费、开源、社区大。</li>
</ol>

<p>盘点结果（关键几条）：</p>
<ul>
<li><strong><code>eth1 = 192.168.100.10/24</code>，故意没有默认路由</strong>，只走宿主入站。所以从 Windows 访问面板要用这个 IP，不是 eth0 的 <code>172.18.x.x</code>。</li>
<li><strong>Docker 29.8.0 已装</strong>，且 <code>registry-mirrors</code> 已经配了 <code>docker.m.daocloud.io</code> + <code>docker.1ms.run</code>（国内加速）——这点很关键，后面在面板里在线拉 AI 镜像不用额外配。</li>
<li><strong><code>in.1panel.cn</code> 直连 000</strong>（DNS 解析失败），<strong><code>resource.1panel.pro</code> 能用但 curl 被限流</strong>——这是后面两个坑的伏笔。</li>
<li>8443 空闲。</li>
</ul>

<h2 id="三、两个坑（先讲清楚，最后一步就顺了）">三、两个坑（先讲清楚，最后一步就顺了）</h2><h3 id="坑-1：官方国内安装源-in-1panel-cn-解析不到">坑 1：官方国内安装源 <code>in.1panel.cn</code> 解析不到</h3><p>1Panel 官方给国内的安装命令是：</p>
<figure class="highlight bash"><table><tr><td class="gutter"><pre><span class="line">1</span><br></pre></td><td class="code"><pre><span class="line">bash -c <span class="string">&quot;<span class="subst">$(curl -sSL https://in.1panel.cn/install_get.sh)</span>&quot;</span></span><br></pre></td></tr></table></figure>

<p>但在 Hyper-V + 这种出网走 <code>eth0</code> 的拓扑里，<code>in.1panel.cn</code> 直接 DNS 解析失败：</p>
<figure class="highlight bash"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br><span class="line">4</span><br></pre></td><td class="code"><pre><span class="line">$ getent hosts in.1panel.cn</span><br><span class="line"><span class="comment"># 无输出（fail）</span></span><br><span class="line">$ curl -sI https://in.1panel.cn/install_v2.sh</span><br><span class="line"><span class="comment"># code:000</span></span><br></pre></td></tr></table></figure>

<p>原因不深究（可能是该域名没接入这台机器出网走的 DNS，或它只在部分网络解析）。<strong>结论：这条路在这台机器上走不通，换源。</strong></p>
<h3 id="坑-2：国内-CDN-resource-1panel-pro-用-curl-下载被-WAF-截断">坑 2：国内 CDN <code>resource.1panel.pro</code> 用 curl 下载被 WAF 截断</h3><p>官方文档给的包地址在 <code>resource.1panel.pro</code>。这个域名 HEAD 请求正常（能拿到 checksums），但 <strong>GET 实际下载被 WAF 限流</strong>——<code>curl</code> 每次只下到 <strong>11MB &#x2F; 65MB</strong> 就断，校验和永远对不上：</p>
<figure class="highlight bash"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br></pre></td><td class="code"><pre><span class="line">$ curl -sL -O 1panel-v2.3.0-linux-amd64.tar.gz</span><br><span class="line"><span class="comment"># 反复都是 11926054 字节（11MB），sha256 与官方 663b495b... 不符</span></span><br></pre></td></tr></table></figure>

<p><code>wget</code> 能下完整，但更稳的是换到 <code>resource.fit2cloud.com</code>（它和 <code>resource.1panel.pro</code> 是同一套包，只是 CDN 不同，这台机器直连没问题）：</p>
<figure class="highlight bash"><table><tr><td class="gutter"><pre><span class="line">1</span><br><span class="line">2</span><br><span class="line">3</span><br></pre></td><td class="code"><pre><span class="line">$ curl -sI <span class="string">&#x27;https://resource.fit2cloud.com/1panel/package/v2/stable/v2.3.0/release/1panel-v2.3.0-linux-amd64.tar.gz&#x27;</span></span><br><span class="line">HTTP/2 200</span><br><span class="line">content-length: 65015800   <span class="comment"># 完整 65MB</span></span><br></pre></td></tr></table></figure>

<p><strong>所以最终下载源用 <code>resource.fit2cloud.com</code>，工具用 <code>wget</code>。</strong></p>
<hr>

</ul>

<p>通用教训（值得记在脑里的几条）：</p>
<ol>
<li><strong>国内源 ≠ 一定通</strong>。官方标榜国内直连的源，在「宿主 DHCP 出网 + 特定 DNS」的拓扑下可能解析失败。先 <code>getent hosts</code> 探一下，再决定走哪个源。</li>
<li><strong>下载工具也是变量</strong>。同一个 CDN，<code>curl</code> 和 <code>wget</code> 的 TLS 指纹&#x2F;UA 不同，WAF 待遇也不同。大包下载前先小范围验证（<code>curl -I</code> 看 <code>content-length</code>），别默认 <code>curl</code> 能下全。</li>
<li><strong>校验和永远要验</strong>。CDN 限流下「下载完成」≠「文件完整」。sha256 对上才敢解压。</li>
<li><strong>别覆盖已有的 daemon.json</strong>。1Panel 默认想帮你配镜像加速，但机器已经配好的话，让 <code>--configure-accelerator n</code> 跳过，避免把现有加速洗掉。</li>
<li><strong>端口监听是「拒绝」与「超时」的分水岭</strong>。<code>ERR_CONNECTION_REFUSED</code> &#x3D; 链路通但无监听（先查 <code>ss</code>）；<code>ERR_CONNECTION_TIMED_OUT</code> &#x3D; 路由&#x2F;防火墙问题（查 <code>ip route get</code>）。</li>
</ol>
