<h1 id="废旧电脑跑本地大模型：从”装不上”到”能聊天”的完整踩坑实录"></a>废旧电脑跑本地大模型：从”装不上”到”能聊天”的完整踩坑实录</h1><p>本地 LLM 部署 · 推理引擎选型 · 模型评测 · 一篇写给同好的实操笔记</p>
<p>前阵子清理硬盘，翻出几个 <code>.gguf</code> 格式的本地大模型文件。本来只是想”试试能不能跑”，结果一路踩坑——网络被墙、引擎不认新架构、模型命名是假的……折腾了一整圈，最终不仅跑通了，还顺手搭了一套可复用的评测环境。本文把整个过程原样记录下来，给想在二手&#x2F;老旧机器上玩本地模型的你少走点弯路。</p>
<p><strong>说明（脱敏）：<strong>文中涉及的具体用户名、绝对路径、内网环境均已做泛化处理；代码里的路径请替换成你自己的实际目录。评测在</strong>纯 CPU</strong> 环境下进行，无独立显卡。</p>
<h2 id="一、先摸底：老机器能不能扛？">一、先摸底：老机器能不能扛？</h2><p>本地推理最怕两件事：<strong>显存不够</strong>和<strong>内存不够</strong>。我的这台机器配置很普通：</p>
<ul>
<li>CPU：一颗 4 核的 Intel 老处理器（支持 AVX2，没有 AVX-512）</li>
<li>内存：16 GB（空闲约 7~8 GB）</li>
<li>显卡：无独显，纯 CPU 推理</li>
<li>系统：Windows 10</li>
</ul>
<p>结论是<strong>够用</strong>。常见的 1B<del>3B 量化模型（Q4 级别）单文件 0.6</del>2 GB，全部能塞进内存。真正卡我的不是硬件，是下面这两关。</p>
<h2 id="二、第一道坎：网络">二、第一道坎：网络</h2><p>做本地部署，第一步几乎都要从 GitHub &#x2F; HuggingFace 拉工具或模型。但我的网络环境一度<strong>访问不了 GitHub</strong>（Releases、各类 ghproxy 镜像全都超时）。这直接卡死了最省事的方案：</p>
<ul>
<li><code>llama-cpp-python</code> 的预编译 wheel 在 GitHub Releases 上 → 拉不下来；</li>
<li>HuggingFace 本体 → 连不上；</li>
<li>源码编译需要本地 C++ 工具链 → 这台机器没有。</li>
</ul>
<p>后来网络恢复后，GitHub 能通了，但 Release 资产下载依然不稳（动不动中断）。<strong>最终的解法</strong>：用脚本对 Release 的 wheel 地址做<strong>分块断点续传</strong>拉到本地，再 <code>pip install --no-index</code> 离线安装；而 <code>numpy</code>、<code>diskcache</code> 这类依赖走<strong>国内 PyPI 镜像</strong>（如腾讯云镜像）就很快。</p>
<p>经验：在国内环境装 Python 包，永远先加 <code>-i https://mirrors.cloud.tencent.com/pypi/simple/</code>（或清华&#x2F;阿里云镜像），能省大量时间。</p>
<h2 id="三、引擎选型：踩了一圈坑">三、引擎选型：踩了一圈坑</h2><p>GGUF 只是个文件格式，真正”让它说话”的是推理引擎。我先后试了三个：</p>
<p>引擎结果原因<br><code>ctransformers</code><br>从 PyPI 直装失败版本太旧，连 Llama-3.2 架构都不认识，遇到非标准架构直接崩溃。<br><code>gpt4all</code><br>走国内镜像装部分可用能跑标准 Transformer（Llama 系），但遇到非标准架构标签直接报错。<br><code>llama-cpp-python</code><br>wheel 断点续传 + 离线装<strong>成功</strong>底层是较新的 llama.cpp，架构兼容最好，三个模型全部加载成功。</p>
<p>结论先行：<strong>本地 GGUF 推理，无脑选 llama-cpp-python</strong>（或它的上游 llama.cpp）。它架构支持最全、社区最活跃，后面所有评测都基于它（0.3.35，CPU 版）。</p>
<h2 id="四、三个模型，三种”人格”">四、三个模型，三种”人格”</h2><p>手头（以及后来陆续往里加的）模型里，最初这三个最有代表性：</p>
<h3 id="①-Hermes-3-Llama-3-2-3B-——-最靠谱的主力">① Hermes-3-Llama-3.2-3B —— 最靠谱的主力</h3><p>真实存在的开源指令模型（NousResearch 出品，Llama-3.2 底座）。中文连贯、会写代码、能出标准 JSON，<strong>安全护栏正常</strong>（明确拒绝危险请求）。规模虽只有 3B，但综合表现最好，<strong>推荐作为日常主力</strong>。</p>
<h3 id="②-TinyLlama-1-1B-Chat-——-快但”莽”">② TinyLlama-1.1B-Chat —— 快但”莽”</h3><p>1.1B 小模型，速度最快（CPU 下 ~22 token&#x2F;s），但能力弱：中文指令遵循差、数学容易胡说、JSON 输出不稳。最要命的是——<strong>它没有安全护栏</strong>，在安全测试中直接把危险步骤列了出来。结论：适合做轻量草稿&#x2F;分类，<strong>别用在面向用户或涉安全的场景</strong>。</p>
<h3 id="③-那个”缝合怪”：qwen3-5-2B-deepseek-v4">③ 那个”缝合怪”：qwen3.5-2B-deepseek-v4</h3><p>这个命名本身就是<strong>警示信号</strong>——“Qwen3.5””DeepSeek v4”都不是真实发布的型号。扒开它的 GGUF 元数据和张量结构后发现：</p>
<ul>
<li>架构标签是自定义的 <code>qwen35</code>，但张量里混着 <code>ssm_a / ssm_dt / ssm_conv1d</code> 等<strong>Mamba 系（状态空间模型）<strong>张量 + Transformer 注意力 → 这是一个</strong>来源不明的混合架构</strong>；</li>
<li>行为是<strong>推理型模型</strong>：先 <code>&lt;think&gt;</code> 思考再作答；</li>
<li>意外的是，它的<strong>安全护栏是正常的</strong>（会引用法律拒绝危险请求）。</li>
</ul>
<p>用对的引擎（llama-cpp-python）它能正常加载、能聊天（~11.5 token&#x2F;s）。但<strong>来源和真实架构核实不了</strong>，我的态度是：当实验对象可以，当主力或上生产不行。</p>
<p>踩坑提醒：下载模型只认 HuggingFace 官方或可信作者。凡是出现”Qwen3.5 &#x2F; DeepSeek v4 &#x2F; 某某 Pro Max”这类<strong>不存在的型号名</strong>，基本都是引流或缝合模型，谨慎对待。</p>
<h2 id="五、评测结果速览">五、评测结果速览</h2><p>我写了一套评测脚本（7 个维度：中文解释、数学推理、代码、知识问答、JSON 格式、安全护栏、指令遵循）+ 速度基准，全在 CPU 下实测。核心数据：</p>
<p>模型速度<br>(CPU token&#x2F;s)中文能力代码&#x2F;JSON安全护栏综合建议<br><strong>Hermes-3-Llama-3.2-3B</strong><del>7.5好好有<strong>推荐主力</strong><br><strong>qwen3.5-2B-deepseek-v4</strong><br>来源存疑</del>11.5中中有可实验，勿上生产<br><strong>TinyLlama-1.1B</strong>~22弱弱<strong>无</strong>轻量草稿专用</p>
<p>注：速度受 CPU、线程数、上下文长度影响很大；有独显时把层数卸载到 GPU（<code>n_gpu_layers</code>）能快数倍。</p>

## 七、给后来者的避坑清单

  - **引擎选 llama-cpp-python**，别在旧引擎上浪费时间。
  - **国内网络装包走镜像**；GitHub 大文件用断点续传，别硬刚。
  - **警惕虚构型号名**的模型，先查架构再下载。
  - **小模型一定要测安全护栏**，TinyLlama 这类无护栏模型别碰敏感场景。
  - **纯 CPU 能玩，但别指望快**；真要日常用，上一张能跑起来的显卡或换 Ollama。
  - 推理型模型会输出思考过程，**对话时默认隐藏、需要时再看**，体验更干净。

## 八、结语

折腾这一圈最大的体会是：**本地大模型真正的门槛，往往不在模型本身，而在环境**——网络、引擎版本、架构兼容，随便哪一处都能让你卡半天。但一旦跑通，那种&quot;模型就在我自己电脑里、不上传任何数据&quot;的踏实感，是云端 API 给不了的。
